# anim-ir v10: the same five briefs after annotations and `compose` (2026-09-05)

## Question

v9 found the format short on exactly two things — a value that stays readable
beside its owner (three writers), and two pictures at once (three writers wrote
two scenes for want of it) — and measured the shortfall as **3 of 8 scenes
falling back to `vector`** with 52 hand-typed positions and 30 colours. Two
generic layers were built from those quotes: five **annotation ops** every
kind accepts over named anchors (`value`, `callout`, `snapshot`, `group`,
`text`), and **`kind: compose`**. This round re-runs the *same five briefs*
with fresh writers and the updated guide, and asks one question: does the
fallback count go to zero?

| agent | model | brief | v9 counterpart |
|---|---|---|---|
| da | sonnet | `concept-vector-clock` | ca: matrix + **vector** (11 positions, 4 colours) |
| db | haiku | `concept-http2-multiplexing` | cb: distributed + **vector** (24, 13) |
| dc | sonnet | `intro-vlmkit-anim` | cc: diagram (0, 0; four storyboard beats dropped) |
| dd | sonnet | `arxiv-batched-pandora` | cd: matrix + state-machine (0, 0) |
| de | haiku | `arxiv-batched-pandora` | ce: **vector** (17, 13) |

**Fallback: 1 of 7 scenes, from 3 of 8.** Both v9 writers who reached for
`vector` only to place known values (ca, cb) now needed no coordinate at all;
ca's two scenes became da's one. The remaining fallback is the same brief and
the same model as in v9 (ce → de): the smaller model chose `vector` before
reading what the other kinds now offer — its log's whole reasoning is "No
built-in kind exactly covers 'boxes in batches with conditional branching'.
`vector` lets us show … text annotations for rewards and decisions", using
the word for hand-placed text nodes and never opening the annotation sheet.
The larger model on the same brief (dd) used `group` for the batch and
`value` for the running totals and typed nothing by hand.

Where the annotations went, they carried what v9 could not:

> da: "every vector display uses the `value` annotation anchored `at` a node
> id, never a literal `pos`/hex … a viewer sees each process's vector update
> at the exact instant of the causal event (verified: `vecB` flips to
> `[1,1,0]` at 1680ms, precisely when B's message lands)."

> dd: "beats 1, 3–6, 8–11 … kept faithfully via `matrix` + `group` (for
> 'batch,' which the kind has no native concept of) + `value` (for running
> totals, which the kind also lacks)."

And the v9 check earned itself: dd's state machine came out 2682px wide,
the new canvas warning said so and named the lever, and dd switched to
`layout: "tb"` in the same round.

## The defect the round found, fixed in this commit

dc wanted the tiny JSON file drawn as a `text` block beside the `file` node —
the guide says every kind takes the five ops and lists `diagram`'s anchors —
and `check` refused it: `sequence[0].text: unknown key "text"`.

> "`array`'s `ops` accepted the identical op, `diagram`'s `sequence` did not,
> contradicting the guide's own anchor table which lists `diagram` anchors
> for exactly this purpose."

The compiler handled it; the validator's action list for `diagram` had not
been extended (it was the one list whose last entry was not `"note"`, and
the edit that extended the others missed it). Fixed, with a test that appends
a `value` op to every kind's example and expects it accepted — the test the
guide's claim always needed. dc folded the snippet into a caption and still
met the brief; the round's one refused annotation was the round's one bug.

## What the writers still could not say

Each of these came from one writer; none repeats across writers the way
v9's asks did. Recorded, not built.

- **A relation between two anchors** (da). `group` around A and C "also
  encloses B sitting geometrically between them — visually misattributing B
  to a claim about A and C only"; `callout` decorates one anchor. The ask is
  "an annotation whose anchor is a *set* of same-kind anchors treated
  pairwise (a 'compare' op drawing an explicit ≤ / ≱ relation between two
  named values, independent of what geometrically sits between their
  positions)". This is the cheapest and most generic of the round's asks: a
  labelled line between two anchors, the one shape the annotation layer
  does not have.
- **Occupancy over time** (db). A two-series `chart` shows *when* each asset
  finished, not the head-of-line blocking that makes it so: "A timeline/Gantt
  kind (lanes for HTTP/1.1 connections + HTTP/2 connection, asset blocks
  sliding left-to-right by transmission time)". db saw `compose` and chose
  the chart for narrative control; this is a kind-level ask, the same one cb
  made.
- **A batch as a native operation** (dd): "open k cells together, one shared
  cost tick" instead of `group` faking it. Reasonable, but specific to this
  brief; `group` did the job.
- **Branching as a primitive** (de), which dd already expressed with
  `state-machine`'s documented `goto` replay.
- **A standing rule on screen** (da, dd): da did not use `text` for the ≤
  definition "because I had nothing schema-appropriate to attach it to";
  `text` without `at` goes to the panel, which the guide says and da did not
  find. A guide sentence, added: the panel is where a rule that governs the
  whole scene belongs.

| IR changes | 0 | 0 | 0 | 0 | 1 + 1 + 1 | 1 validator fix |

Ten rounds, forty-five agents. The two layers took the fallback from three
scenes to one, and the one that remains is a model that did not read the
sheet rather than a thing the sheet lacks. The asks have changed shape: v9's
were the same three things from several writers each; v10's are five
different things from one writer each. That is what "the format is no longer
short" looks like from inside the loop — the next round should be a re-edit
round on these scenes (does a `value` survive someone changing the data it
tracks?), not another expressiveness round.

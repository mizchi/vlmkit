# anim-ir v1: can a fresh agent write a correct scene from the guide alone? (2026-09-04)

## Question

The IR was designed against two criteria: an agent produces it correctly from
little context, and intent stays readable on re-edit. This run measures the
first. Six fresh subagents each got one brief from
`fixtures/anim-scenario/briefs/` and `docs/anim-ir.md` (the one-page writing
guide), nothing else — the implementation, its fixtures, and other attempts
were named as forbidden. Budget: 4 rounds of `vlmkit anim check`. Round 1 was
required to be a finished attempt, so its ✗ count is a measurement.

Three agents ran on Sonnet, three on Haiku, to see whether the smaller model
needs the checker's hints more.

## Result

| agent | model | kind | first `check` | rounds | scene → timeline | duration | brief met |
|---|---|---|---|---|---|---|---|
| a | sonnet | sort (insertion, explicit ops) | clean | 1 | 1948 B → 8124 B (×4.2) | 7.96 s | yes |
| b | sonnet | state-machine (TCP teardown, 6 states) | clean | 1 | 733 B → 5455 B (×7.4) | 4.83 s | yes |
| c | haiku | distributed (Raft election, lost message) | clean | 1 | 894 B → 7471 B (×8.4) | 4.08 s | yes |
| d | haiku | diagram (cache-aside, hidden node) | clean | 1 | 686 B → 4147 B (×6.0) | 4.76 s | yes |
| e | sonnet | heap (priority queue, note before pop) | clean | 1 | 257 B → 8264 B (×32) | 9.79 s | yes |
| f | haiku | vector (three easings) | clean | 1 | 1052 B → 1388 B (×1.3) | 2.80 s | yes |

6/6 first attempts passed with zero errors and zero warnings; every agent
judged its own output would teach the concept after looking at rendered
frames. The first-attempt-correctness axis is saturated at this budget, for
both model sizes, so the information in this run is entirely in the friction
quotes below. The re-edit axis is untested and is v2's question.

The per-scene expansion ratio is the semantic layer's value made visible:
`heap` gets 32× because the compiler runs the heap; `vector` gets 1.3× because
the writer is already speaking in tweens.

## What worked — the agents' words

> "Hidden nodes and edges stay invisible until a `show`" — This single sentence was load-bearing. (d)

> the transitions table row `{"from","to","on","note"}; one per (from, on)` directly told me FIN_WAIT_1 could carry two outgoing transitions (on ACK, on FIN) without conflict (b)

> "Captions are the explanation... write them for the reader, not the machine" correctly pushed me away from the `algorithm` shorthand toward explicit `ops` so I could guarantee the required "sorted run" language. (a)

> the `"lost": true` field on messages explicitly solves "no message silently lands on down node" (c)

Reading: the field tables plus one runnable example per kind were sufficient.
Nobody needed the checker's hints, so their quality is unmeasured by this run
(unit tests cover the phrasing; an agent has not yet needed one).

## What didn't / new gaps

### G1 — beats that start at the same instant lost a caption (c)

> The message from n2 to n1 is compiled and animated correctly but produces no caption line. A first author might assume all messages create steps.

Root cause: not "lost messages have no caption" as the agent inferred, but two
messages with the same `at` produced two steps at one `t`, and the builder let
the second replace the first. Real narration went missing from `explain`.

**Fixed in this commit:** steps at the same instant are merged and their
captions joined with " · "; a test pins it. The guide now defines a *beat* as
one step and says what happens when two coincide — c also asked for the word
to be defined.

### G2 — the compiler's own steps and op semantics were undocumented (a, d, e)

> `explain` showed 24 steps against my 22 authored ops: the tool silently prepends a "Start: …" step and appends a "Sorted: …" step — undocumented (a)

> nothing documents whether `compare` alone moves anything (a)

> the guide says `{"note": "…"}` is a "captioned pause" but doesn't explicitly state it counts as a step marker (d)

> The heap section never shows a `note` op example (e)

**Fixed in this commit:** a "three conventions" block in the guide (caption
overrides, `note` is a step whose string is the caption, compilers add a
first and last step), `compare` / `swap` / `done` semantics spelled out under
`sort`, and a `note` in the heap example.

### G3 — nothing warned about a drawn-but-never-animated path (b)

> CLOSING and its two edges got 0 warnings even though they're inert throughout; I only learned this behavior by observing the clean result

A viewer sees a box and never learns when it is entered. **Fixed in this
commit:** the state-machine check warns for each reachable state the trace
never enters and each transition it never fires, with the hint to extend the
trace or explain the path in a caption. b's scene now gets 2 warnings (the
CLOSING state and the FIN_WAIT_1 —FIN→ CLOSING transition; CLOSING's own
outgoing edge is not repeated, since its source is never visited), which is
the right answer for it.

### G4 — no escape hatch when the state-machine layout is wrong (b)

> `state-machine` has no `pos`-pinning like `diagram` does … fully automatic with no escape hatch

**Fixed in this commit:** `states[].pos` pins a state; the rest are laid out around it.

### G5 — pacing (a) and a duration budget (e)

> non-uniform per-step timing so "why it stops" beats can linger longer than mechanical compare/swap beats (a)

> the brief's "under 20 seconds" constraint has no corresponding assertion in `check` (e)

**Fixed in this commit:** sort ops accept `ms`; `check --max-ms N` fails over budget.

### Deferred

- **Multiple traces** on one state machine (b: "if the format allowed a second trace"). Worth doing once the re-edit run says how people structure alternatives; a caption on the unused path is the workaround the new warning points at.
- **A sorted-run bracket** under the bars (a) and **an array view beside the heap tree** (e). Both are compiler additions to one kind, not IR changes; neither blocked correctness.
- **Data labels on tokens** in diagrams (d: "explicit data labels (e.g., 'key not found')"). `relabel` covers node text; token text does not exist yet.

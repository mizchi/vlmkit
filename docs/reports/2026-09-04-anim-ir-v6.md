# anim-ir v6: re-editing matrix, graph and chart scenes (2026-09-04)

## Question

v5 showed the three new kinds are correct on the first attempt from the
guide. The axis that found the IR's real flaws before (v2–v4) was re-edit:
open an existing scene, apply a change request, and see whether the intent
survived the format. Three frozen scenes in `fixtures/anim-scenario/re-edit/`
and three change requests, each built to probe the one convention in its kind
that could mislead an editor:

| agent | model | scene | the probe |
|---|---|---|---|
| x | haiku | `matrix-pivot` (Gaussian elimination with a row swap) | cell references are **by current position**: after the swap, does "clear the middle row" get written as `[1, 0]`, and does the editor know that row is the original `r0`? |
| y | sonnet | `graph-bfs` (hand-written BFS that stops when Dan is found) | add `Fay` (Cat–Fay, Fay–Dan): does the editor realise the shortest route to Dan is unchanged and leave the walk alone, and does a discovered-but-never-dequeued node read as amber rather than green? |
| z | haiku | `chart-regions` (two series, one incident) | add a third series with its own incident and correct a value: does every series get its reveal, does the axis top recompute, is the threshold left where it belongs? |

Each agent wrote its prediction (the final grid / the green nodes and edges /
the axis top) before the first `check`.

## Result

| agent | first `check` | rounds | prediction | brief met |
|---|---|---|---|---|
| x | 0 ✗ 0 ⚠ | 1 | final grid correct row by row | yes — middle row `0, 2, 1, 4`, bottom `1, 1, 1, 6`, narrated as "already clear" |
| y | 0 ✗ 0 ⚠ | 1 | "identical in every particular" | yes — Fay added with both edges, ops untouched, Fay white, Cat amber |
| z | 0 ✗ 0 ⚠ | 1 | axis 2.5 predicted, 3 actual | yes — six beats in order, Thursday bar at 1.2, no `yMax` |

3/3 clean, 3/3 correct, nothing unintended moved. The v2 pattern (an edit
that silently shifts something the editor did not touch) did not recur:
matrix references by position were applied to the right row on the first
try, the graph edit changed exactly the two lists it had to, and the chart
axis recomputed without the editor pinning it.

The one prediction miss is z's axis top: 2.5 expected, 3 actual, because the
guide said "a round number just above the largest value" and did not say
"10% above, rounded up a 1-1.5-2-2.5-3-4-5-6-8 ladder". A doc sentence, and
the number the agent got was still a sensible axis.

y's edit is the most informative. The change request said "the walk must
now find Dan through the shorter of its two routes" — a trap, since the new
route is longer. y read the ops, saw that Bob is dequeued before Cat, noted
that Fay "is never discovered by this particular hand-written walk
regardless of her existing in the graph", and changed only `nodes` and
`edges`. It then predicted Cat would end amber (highlighted, never visited)
and Fay white, and both held. That is intent surviving re-edit in the sense
the criterion means: the editor could see what the walk does without playing
it.

## Friction, all documentation (fixed in this commit)

- **y**: "`highlight`'s resulting colour is never named in the guide … I
  confirmed Cat renders amber, not green, only by rendering the SVG." The
  Colours paragraph now names amber, says a highlighted node stays amber
  until a `visit` / `path` / `unhighlight`, and adds "use explicit ops when
  the walk should be allowed to stop before reaching everything" — y's
  second point, that the algorithm-visits-everything rule is why the README
  banned `algorithm`, was true and unstated.
- **z**: "the yMax rounding algorithm is undocumented"; "each series must be
  revealed explicitly … this sentence would have clarified". Both added to
  the chart section.
- **x**: "the guide does not show an example where a `set` assigns a value
  already present"; row labels travelling with rows "could be more explicit".
  One sentence each in the matrix section.

## Stopping, again

Six rounds, twenty-six agents. The three kinds added today have now passed
both axes the first six were held to, and the last two rounds changed only
documentation. The IR is stable enough to release as a prototype; the open
PR is [mizchi/vlmkit#131](https://github.com/mizchi/vlmkit/pull/131).

Things the loop did not test and a later round could: a scene long enough
to need `--max-ms` budgeting across kinds; `vector` re-edit (the only kind
never re-edited); a re-edit by a *different* model family than the author.

# anim-ir v5: three new kinds, from the guide alone (2026-09-04)

## Question

`matrix`, `graph` and `chart` landed today to widen what the IR can say
(grids and tables with row / column operations, traversals, series data).
Each has a new vocabulary, so the question v1 asked of the first six kinds
is asked again of these three: **does a fresh agent write a correct scene
from `docs/anim-ir.md` alone**, and where does it stumble? Four briefs, four
agents, mixed models, same rules as before (brief + guide only; no source,
no design notes, no other attempts).

| agent | model | brief | what it exercises |
|---|---|---|---|
| t | sonnet | `matrix-knapsack` | DP fill with `from` cells (one and two sources), `mark`, labels in captions |
| u | haiku | `graph-friend-of-friend` | explicit ops by hand (no `algorithm`): visit / explore / label / path |
| v | haiku | `chart-deploy-frequency` | reveal order, `threshold` mid-story, `highlight` by series, `set` |
| w | sonnet | `graph-build-critical-path` | directed Dijkstra with `goal`, two nodes pinned + `lr` layout, predicted captions |

## Result

| agent | first `check` | rounds | scene bytes | brief met |
|---|---|---|---|---|
| t | 0 ✗ 0 ⚠ | 1 | 1824 | yes — cell (3,5) = 6 and marked |
| u | 0 ✗ 0 ⚠ | 1 | 1469 | yes — path Ann → Bob → Dan → Fay green, all six reached |
| v | 0 ✗ 0 ⚠ | 1 | 845 | yes — six beats in the brief's order, Q4 set to 11 |
| w | 0 ✗ 0 ⚠ | 1 | 496 | yes — predicted both relaxation captions, `core` left / `web` right |

4/4 clean on the first attempt, every guess the agents reported turned out
right. w predicted the generated Dijkstra narration before running it and
got both relaxation lines ("utils → api: 2 + 1 = 3 < 5, improve") word for
word except the phrasing of "improve". That is the same result the first six
kinds had in v1 (6/6): a worked example per kind plus a field table is
enough for first-attempt correctness. The axis where the IR was wrong in
v2–v4 was re-editing, which these kinds have not been tested on yet.

## Friction, all documentation

None of the four found a missing construct; every item is a sentence the
guide did not have. All fixed in this commit.

- **t**: "the guide never shows what the *generated* caption looks like for a
  `from` with one vs. two sources" and "every guide example shows only
  single-entry `from`, so this was unconfirmed by the doc itself". The guide's
  edit-distance example now takes a min over three cells, and a sentence
  gives the default caption's shape and says it names the inputs but not why
  one won.
- **v**: "`highlight: {series, index | category}` is ambiguous — it should
  explicitly state use one of … and show an example with each"; "doesn't show
  what auto-captions look like"; "doesn't explain *when* to place a
  threshold". The chart section now spells out the three target shapes, the
  default reveal caption, and "put a threshold at the beat where it becomes
  relevant".
- **w**: "the `graph` kind's field table never says whether `pos`-pinning a
  subset of nodes coexists with `layout` — only the diagram kind spells that
  out". Added to graph's `layout` row.
- **u**: colour semantics — "unclear if `visit` automatically greens a node or
  is temporary", "whether applying `path` after `visit` leaves visited nodes
  outside the path coloured", "nodes you never visit stay default". A
  "Colours:" paragraph in the graph section now states all four.

Also from t, not a guide problem: `check` reports the minified scene size
while the file on disk is pretty-printed, "worth knowing since the two don't
match". Left as is — the metric is bytes of intent, not bytes of whitespace —
but the report line could say "minified".

## What the round says about the new kinds

- **matrix** carried the hardest brief (a DP with a real choice per cell) and
  the agent's only wish was a sentence about default captions. The
  `[row, col]`-by-current-position rule "settled the coordinate convention
  with zero guessing".
- **graph** worked both ways it is meant to: generated (w: the `dijkstra` +
  `goal` example "was copy-adaptable almost verbatim") and hand-written (u:
  "op types … map directly to BFS steps"). u's brief asked for a walk that
  stops when Fay is found; the agent's BFS reached everyone before painting
  the path, which the brief allowed and the checker cannot judge — a
  narrative choice, not a tool gap.
- **chart** needed the least: 845 bytes for a six-beat story, first try, from
  a Haiku agent.

## Next

The three kinds have passed the axis the first six passed in v1. The axis
that found real flaws before — re-edit an existing scene and see whether
intent survived — has not been run on them. A v6 re-edit set would be: swap
two rows in a matrix scene that later `set`s cells by position (does the
by-current-position rule read the way the editor expects?); add a node and
an edge to a graph scene with explicit ops (does the hand-written walk still
narrate correctly, and does the checker catch an explore over a missing
edge?); add a series to a chart with a hand-written sequence (does the
never-revealed warning fire, and is the axis recomputed?).

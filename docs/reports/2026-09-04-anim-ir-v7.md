# anim-ir v7: `array` and `tree`, both axes in one round (2026-09-04)

## Question

Two more kinds landed for the patterns CS explanations reach for most and
the IR could not say: `array` (named pointers, a window bracket — binary
search, two-pointer, sliding window; `sort` only speaks in swaps) and `tree`
(a BST with insert / search / delete / traverse; `heap` is fixed slots and
`graph` cannot change shape). Since v5 and v6 had shown the two axes can be
run together, this round did both at once: one fresh brief and one re-edit
per kind, four agents.

| agent | model | task | what it exercises |
|---|---|---|---|
| aa | sonnet | brief `array-partition` | a Lomuto partition written entirely by hand: two pointers, compare / swap per step, `mark` the pivot |
| ab | haiku | brief `tree-bst-lesson` | sorted inserts degenerate to a chain; a 7-comparison search; a `note`; two more inserts; in-order traversal |
| ac | haiku | re-edit `array-two-sum` (target 13 → 15) | rewrite a hand-written pointer walk so every comparison is a beat |
| ad | sonnet | re-edit `tree-delete` (leaf → two-children case) | predict the successor and where the displaced child ends up, then narrate it |

Every agent wrote its prediction (final row / comparison count and landing
spots / the (i, j, sum) sequence / the successor) before the first `check`.

## Result

| agent | first `check` | rounds | prediction | brief met |
|---|---|---|---|---|
| aa | 0 ✗ 0 ⚠ | 1 | final row `2, 4, 3, 5, 9, 8, 7`, pivot green at index 3 | yes |
| ab | 0 ✗ 0 ⚠ | 1 | 7 comparisons; 35 under 40, 45 under 50 — all exact | yes |
| ac | 0 ✗ 0 ⚠ | 1 | (0,6,13) → (1,6,15), pair {1, 6} — exact | yes |
| ad | 0 ✗ 0 ⚠ | 1 | successor 35, 40 becomes its right child, 45 already gone — exact | yes |

4/4 clean, every prediction right, no diagnostic fired for anyone. The
hand-written partition (aa) is the most demanding scene any agent has
written in these rounds — 22 authored beats with a pointer moving on every
one — and it was correct from the field table alone: "Indices are 0-based
positions and every pointer has its own lane removed the biggest ambiguity".
ad computed a two-child BST deletion by hand from one sentence of prose and
one example and matched the compiler's successor, depth and displaced child
exactly.

## Friction, all documentation (fixed in this commit)

- **ac**: "the guide does not explicitly state whether moving pointers
  creates a step … inferred rather than stated." The conventions list now
  says every op is its own beat by default and which ops `ms: 0` folds.
- **aa**: partial pointer updates (`{"j": 1}` leaving `i` alone) and "compare
  moves nothing" were stated only under `sort` or by a single example. Both
  are now in the `array` ops row, with "pointers stay on their indices"
  after a swap.
- **ab**: "for a search, the final beat comparing for equality counts as one
  of the comparisons" and "the traversal output appears as step text" —
  both added to the tree prose.
- **ad**: "the guide never states what happens to the displaced subtree when
  the successor has its own right child." Added: that child takes the
  successor's old spot.

## What the round says about the new kinds

- `array` reads the way its authors think: pointers by name, indices by
  position. Nobody asked for a generator they did not have; two of the four
  tasks deliberately forbade `algorithm` and were still first-try correct.
- `tree`'s compiler-run semantics (comparisons narrated one per beat,
  successor promotion drawn as a slide) let an editor predict the picture
  from the rules. ab's "no guesses proved wrong; the guide was
  self-consistent and the tool honored the spec" is the criterion met.
- Lesson-shaped briefs (ab: "each beat says why, not just what") were met by
  mixing generated comparison captions with authored captions on the last
  beat of an op and `note` pauses — the caption model carried without a new
  construct.

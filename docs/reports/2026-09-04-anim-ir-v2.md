# anim-ir v2: does intent survive a re-edit, and does the smallest context suffice? (2026-09-04)

## Question

v1 saturated first-attempt correctness (6/6 clean from the guide alone), so
this run tests the other design criterion — **intent readable enough to edit**
— and pushes the first one harder: the smallest context (the CLI's own schema
sheet, no guide) and a brief whose warnings the agent must clear rather than
accept. Four fresh agents, run against the tool as fixed after v1:

| agent | model | task | context given |
|---|---|---|---|
| g | sonnet | re-edit: slow the replica's ack to 1200ms with a captioned reason, add a `backup` node that receives a copy right after | the scene file, `explain`; guide allowed only after a cold reading |
| h | haiku | same re-edit | same |
| i | haiku | insertion-sort brief | `vlmkit anim schema --kind sort` only — no guide |
| j | haiku | TCP teardown brief with an alternative path; must end with **no warnings** | the guide |

## Result

| agent | first `check` | rounds | outcome |
|---|---|---|---|
| g | clean | 1 of 3 | edit correct; **manually re-timed two absolute events** to keep the story |
| h | clean | 1 of 3 | edit correct; **did not re-time the events — story silently broken** |
| i | clean | 1 of 4 | brief met via `algorithm: "insertion"`; generated captions carried the required language |
| j | 2 ⚠ | 4 of 4, **then dropped the alternative path to get to zero warnings** | brief NOT met |

Two of the four runs are failures of the tool, not of the agents, and the
same failure showed up twice from independent directions:

- **g and h**: `events[].at` is absolute while message timing is relative, so
  lengthening one latency moved every later message but not the crash. g caught
  it by hand; h shipped it, and `check` was clean both times.
- **j**: v1's new "drawn but never taken" warning carried the hint "mention it
  in a caption" — and the state-machine kind had no place for a caption. A Haiku
  agent spent three rounds trying to obey the hint, then deleted the path the
  brief asked for. The warning was right; the remedy it named did not exist.

## The agents' words

### G6 — absolute event times drift when message timing changes (g, h)

> `messages[].at` is relative-by-default and shifts automatically when you insert or delay a message; `events[].at` is absolute and does **not**. Adding the 1200ms ack delay + one new message pushed every later message +1200ms, but the two absolute events stayed put — `check` still passed clean, silently producing a scene where primary sends "ok" *after* its own crash event. (g)

> The event "primary crashes" is at absolute 2500ms. After my latency change, this event now falls between the backup message (2400ms) and ok message (3000ms), creating a seemingly illogical narrative sequence … The file allows this without warning. (h)

> `events[0].at: 2500` / `events[1].at: 3000` gave no indication they were hand-tuned to land "100ms after the lost write is sent" and "exactly when the retry lands" — I only recovered that by diffing against `explain`'s send/land times (g)

**Fixed in this commit.** Two changes, one to the IR and one to the check:

1. `after: "<message label>"` (+ optional `delay`) on both events and messages
   anchors them to *when a named message lands*. The intent g had to reverse-
   engineer ("exactly when the retry lands") is now the literal text of the
   file: `{"after": "write x=2", "node": "replica", "status": "leader"}`. The
   guide and the schema sheet show `after` first and call `at` fragile.
2. When an absolute `at` is still used, `check` warns if the event lands while
   a message is in flight, naming the message and the `after` that would pin
   it, and warns when a node sends a message after it went down. Re-running the
   unmodified round-2 scenes: h's scene now gets both warnings (the exact story
   break h described); g's gets one (its crash was hand-placed 100ms after a
   send, so the warning is a true positive about fragility and a false alarm
   about intent — a warn, not an error, is the right severity).

### G7 — a warning whose hint named a remedy the format did not have (j)

> Checker suggested: "mention it in a caption so the viewer knows it is an alternative path" … State object schema accepts only: `id`, `label`, `final`, `pos` — no `caption` field … Trace field accepts only string event names, not `{"note": "..."}` objects … The alternative hint ("extend the trace") is impossible for deterministic FSMs — both execution paths cannot occur in a single trace execution.

> Had to choose between guide compliance (no warnings) and brief compliance (include alternative path). Chose no warnings, omitting the simultaneous-close scenario.

This is the v1 fix for b's finding causing a worse outcome than the gap it
closed, and it is the most valuable result of the run: a hint is a promise,
and an agent that takes it literally will destroy content to keep it.

**Fixed in this commit.** The trace accepts four item shapes: an event name,
`{"on": ev, "caption"}` to narrate a step, `{"note": "…"}` for a captioned
pause, and `{"goto": state, "caption"}` — the token jumps without a transition,
which is how a second path is played after the first has ended. The hint now
names exactly these. j's round-1 scene with the CLOSING path plus one `goto`
leg compiles clean with the alternative narrated:

```
 5. [ 3500ms] on timeout: TIME_WAIT → CLOSED
 6. [ 4480ms] Simultaneous close: the peer's FIN arrives before our ACK
 7. [ 5040ms] on FIN: FIN_WAIT_1 → CLOSING
 8. [ 6020ms] on ACK: CLOSING → TIME_WAIT
```

This also covers b's v1 request for "a second trace".

### What worked

> "algorithm": "bubble" | "insertion" | "selection" — generates the ops by running the algorithm; use this unless you need a custom walk — This one line provided everything needed. (i, schema sheet only)

> `explain` matched this reading exactly. (g, on the cold read of a 771-byte scene)

> Cold reading took ~2 minutes (h) / ~6 minutes reading the raw JSON before feeling ready (g)

The schema sheet alone was enough for a Haiku agent to meet the sort brief,
so the "little context" criterion holds at the one-screen level, not just the
one-page level. Both re-edit agents recovered the story from the file plus
`explain` without the guide; the guide was opened for one field each
(`latency`, `at`).

### Also asked mid-run: does a contact sheet help a vision model?

The user asked whether sending frames as one sliced image improves a VLM's
read. Yes with limits (relative judgement across tiles beats absolute reads;
one image is one call and fixes the order; tiles under ~300px lose in-frame
text; correctness stays with `check`). `vlmkit anim sheet scene.json --out
sheet.png` now produces that image — every step as a tile labelled with step,
time and caption — and the guide has a short section on when to use it.

### Deferred

- i: "Whether generated captions would include the word 'sorted run' (they do)" — the schema sheet could quote one generated caption per algorithm. Cheap; left for when a run actually needs it.
- h: "Why do events use absolute times but most messages don't?" — `after` removes the need for absolute `at` in most files; removing `at` from events entirely would break nothing shipped but is a v2-IR decision to make with more scenes in hand.
- g: `caption` on a message *replaces* the generated "a → b: label" line rather than adding to it. Documented in v1's conventions; whether the generated line should be kept as a prefix is a taste call, not yet forced by a failure.

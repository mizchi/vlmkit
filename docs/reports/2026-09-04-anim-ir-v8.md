# anim-ir v8: stack, queue, list — and the first `vector` re-edit (2026-09-04)

## Question

Three kinds landed for the structures that `array` cannot say because its
length is fixed: `stack` (LIFO column), `queue` (FIFO row, the rest shift
forward) and `list` (a singly linked list with insert / remove / find /
reverse). Same two axes as v5–v7, plus one debt: `vector`, the generic kind,
had never been re-edited. Five agents.

| agent | model | task | what it exercises |
|---|---|---|---|
| ba | haiku | `stack-postfix`: evaluate `3 4 + 2 *` | several ops per token, operand order in captions |
| bb | sonnet | `queue-bfs-frontier`: only the BFS queue is drawn | captions carrying facts the picture lacks, `peek` before `dequeue` |
| bc | sonnet | `list-lru`: an LRU cache as a list | "move to front" as remove + insert at 0, eviction as remove of the tail |
| bd | haiku | re-edit `list-playlist`: duplicate value, reverse, find from the new head | `after` with duplicates, what reverse does to the head, hop counting |
| be | sonnet | re-edit `vector-loader`: turn a pause into a stall | `x` as the centre, `"<"` after a `wait`, total duration arithmetic |

finding of the round.

## The finding: a warning the writer cannot fix is a compiler bug

bc did what the loop asks for and went further: rather than accept two ⚠,
it wrote scratch scenes until it had the rule — "any `remove` followed later
by any `insert` leaves exactly one dead `arr-N.opacity` track and a ⚠,
independent of value, position, or spacing" — and concluded "2 ⚠ appear
unavoidable using only the documented op vocabulary … Without it I couldn't
tell from the guide whether the ⚠s meant my scene was wrong."

It was right. The list compiler re-set every arrow's opacity on every
relink, so an arrow slot that a remove had freed and an insert later reused
carried a track whose keyframes were all `0` — the generic "the track
changes nothing" warning fired on the compiler's own bookkeeping. Fixed by
setting opacity only when it changes (the same `show` helper the collection
compiler already used), with a regression test on bc's exact shape. All
five scenes now check with 0 ⚠ unchanged.

The rule this adds to the package, next to "every hint must name a remedy
that exists": **every warning must be about the scene.** A diagnostic the
writer cannot act on from the documented vocabulary is a defect in the
compiler, and the writer's investigation of it is the bug report.

## Friction, documentation (fixed in this commit)

- **bb**: "the guide never states what a default dequeue / peek caption
  looks like … nor that the compiler's own last step names every value that
  was ever pushed / popped". Added to the stack / queue prose, with ba's
  point that one token needing several operations is several ops.
- **bd**: "hops was never formally defined"; reverse with duplicate values.
  Added: hops are arrows followed from the head, a value at the head is 0
  hops; `after` / `remove` / `find` mean the first match; duplicates are
  separate boxes.
- **be**: whether `"<"` can attach to a `wait` (it can — verified, the tween
  starts when the wait starts) and that an item with neither caption nor
  label is motion only and gets no `explain` line. Both added to the vector
  table.
- **bc**: the LRU idiom (remove + insert at 0) is the brief's, not the
  guide's; no vocabulary added — the point of the kind is that the idiom is
  expressible without one.

## `vector` under re-edit

be predicted the 60% state (`x = 60 + w/2 = 132`, `w = 144`) and the new
total (2700 ms) from two guide sentences and the existing file's own
pattern, and every number matched. The generic kind holds up on the axis the
semantic kinds were held to: the coordinate convention and the sequencing
rule are stated once and are enough.

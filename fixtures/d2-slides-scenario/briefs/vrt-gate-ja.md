# Brief: 「VRT ゲートを CI に入れる」— 社内勉強会のスライド（日本語）

社内のフロントエンド勉強会で 10 分話す。聞き手は VRT（Visual Regression
Testing）を「スクリーンショットを目で見比べるもの」だと思っている。デッキを作る。

日本語で書くこと。図のラベルも日本語でよい。

## 話すこと

1 スライド 1 項目、この順で:

1. **タイトル。** 「壊れたページには失敗状態がない」。サブタイトルで、
   これが VRT ゲートを CI に入れる話だと分かるようにする。
2. **今どうなっているか。** スクリーンショットを目で見比べる運用は、
   見落としが検出漏れとして残り、しかも「見た人が気づかなかった」以外の
   記録が残らない。
3. **ゲートとは何か。** ページを測って、しきい値を割ったら exit 1 を返すもの。
   **図つき**: `ページ` → `測定` → `判定` → `exit 0 / exit 1` の流れ。
4. **どの測定を先に入れるか。** 壊れ方の検出（要素の重なり、はみ出し、
   何も描画されていない）が最初の一本。次に文言、次にコントラスト。
   **図つき**: 3 つの測定を並べ、最初に入れるものを強調する。
5. **通るだけのゲートは信用できない。** わざと壊して落ちることを確かめる
   ステップを CI に入れる。なぜ必要かを一行で。
6. **まとめ。** 覚えて帰ってほしい一行。

## 必須の文言

ビルドされた `copy.txt` に、以下がそのまま含まれていること:

- `壊れたページには失敗状態がない`
- `exit 1`
- `わざと壊して落ちることを確かめる`

## 完了条件

「ビルドできた」では終わりではない。納品するビルドで 4 つすべて:

1. ビルドが exit 0 で、**stderr に警告が出ていない**。
2. `check integrity` が `index.html`（既定の 3 ビューポート全部）と
   `print.html --viewports 1280` の両方で CLEAN。
3. `check copy --manifest <built>/copy.txt --allow-invisible unknown` が
   **missing 0**。
4. `print.html` の `check a11y contrast` が **0 failures**。検査要素数は
   全スライドが読まれている数（目安でスライド 1 枚あたり 10 以上）であること
   — 数個しかないなら `index.html` を指している。

ゲートの指摘がデッキのソースからはどうしても直せないと判断した場合は、
そこで止めてよい。何をどう判断したか、直すには何が必要かを書き残して、
ビルドはそのまま納品すること。

加えて、上の図がすべて存在し、必須の文言 3 つが `copy.txt` にあること。
